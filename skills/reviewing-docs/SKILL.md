# 文書をレビューする

書き方の規則は`skills/writing-docs/SKILL.md`にある。
レビューはその規則に照らして行い、文書は自分で直さない。

## 見るもの

1. 文章: Skill ツールで`yomiyasu`を呼び、その規範で読む。
   元の主張、比重、言い切りの強さ、文の働きが崩れていないかを見る。
2. 事実: 文書に書いたコマンド、パス、設定の値が、リポジトリの実物と合っているか。
   コマンドは実際に叩き、パスは存在を確かめる。
3. 図: `.omm/`の図と説明が、今のコードと合っているか。
   `just omm diff <要素>`で前の図との差を見る。
   ずれていれば、`oh-my-mermaid:omm-scan`で更新するよう指摘する。
4. 置き場所: 文書が`docs/`にあるか、直下に置いてよいものか。
5. 書いてはいけないもの: 管理番号、TLA+の性質の名前、秘密情報。
6. リンク: 文書間のリンクが切れていないか。

## 機械の検査

`just docs-check`(mado、typos、`omm validate`)と、yomiyasuの検査スクリプトを回す。
どちらかで落ちていれば、それも指摘に含める。

## 報告

指摘は一度にまとめて返す。
各指摘には must / should / nit を付け、ファイルと行を示す。
最後に、統合してよいかを「合格」か「不合格(must が残る)」で書く。
指摘が無ければ「指摘なし」と書く。
