# 並列に回す

品質ゲートの中身と閾値は変えない。
変えるのは、回す回数と順番と、手元の環境変数だけである。

## 担当を起こす前に親がそろえること

- `rustc --version` が `rust-toolchain.toml` の版を返すことを確かめる。
  ほかの場所の cargo が先に見つかるなら、
  PATH の先頭に `$HOME/.cargo/bin` を置く。
- ツールチェーンの入れ直しは親が1回だけ行う。
  担当が同時に `rustup` を回すと、入れ直しがぶつかって部品が欠ける。
- macOS では `rust-code-analysis-cli` を `cargo install` で入れる。
  手順は `.config/aqua/registry.yaml` の注にある。
- ブラウザの契約テストに要る Chromium は、
  親が `just install-browsers` で1回入れる。
  `PLAYWRIGHT_BROWSERS_PATH` は全員で同じ値にする。
  無いと契約テストが `NotInstalled` で落ちる。

## 担当がすること

### ビルドの置き場は worktree ごとに1つ

- `just` を通すと、その worktree の中の `target/` を使う。
- `cargo` を直接叩くときは、`--target-dir <worktree>/target` で同じ場所を渡す。
- 依存のコンパイル結果は sccache で使い回す(下の環境変数)。

### 全体のテストとカバレッジは PR の CI で回す

- 手元では、触ったモジュールのテストだけを回す。
  `cargo test -p <crate> <テスト名の一部>` の形で回す。
- コミットのフックは、整形、clippy、複雑度、文書、設定、秘密情報の検査だけを回す。
  コミットの前に `just fmt-check` と `just clippy` を手で回すと、この2つでは落ちない。
- 全体のテストとカバレッジ100%は、PR の CI の `check` ジョブで確かめる。
  手元で全体を回すと、カバレッジの計測用のビルドで数分かかる。
- 手元で全体を回す必要があるときは `just check-serial` を使う。
  その worktree の置き場のロックを取ってから `just check` を回すので、
  同じ worktree で2本が同時に測って実行ファイルが消えることがない。

### 環境変数

| 変数 | 値 | 効くこと |
|---|---|---|
| `CARGO_BUILD_JOBS` | `2` | 並列の担当とメモリを取り合わない |
| `CARGO_PROFILE_DEV_DEBUG` | `line-tables-only` | ビルドのメモリとディスクが減る |
| `RUSTFLAGS` | `-C link-arg=-fuse-ld=lld` | リンクが速くなる |
| `RUSTC_WRAPPER` | `sccache` | 新しい置き場でも、依存のコンパイル結果を使い回す |

- デバッグ情報を減らしても、カバレッジの結果は変わらない。
- `RUSTFLAGS` は、lld が PATH にあるときだけ付ける。
  macOS では `ld64.lld`、Linux では `ld.lld` である。

- 置き場は worktree ごとに1つ、その worktree の中の `target/` にする。
  担当もレビューも、それ以外に置き場を作らない。
  worktree をまたいで置き場を共有しない。
  同じ名前のクレートの成果物が上書きし合い、
  別の worktree のコードでビルドが落ちる。
- 置き場は1つで数GBになる。
  2026-10-20 には、担当ごとに置き場を増やしてディスクが埋まり、全部の担当が止まった。
  単位が main に入ったら、その worktree を片づけて置き場ごと消す。
  手順は下の「親セッションがすること」にある。
- 置き場は `CARGO_TARGET_DIR` でなく `--target-dir` の引数で渡す。
  sccache は `CARGO_` で始まる環境変数をキャッシュのキーに入れる。
  置き場を環境変数で変えると、キャッシュに当たらない。
- 全員が同じ値を使う。値が違うと、sccache のキャッシュに当たらず、依存のビルドがやり直しになる。
- 値は手元の環境変数で渡し、リポジトリの設定には書かない。
  CI の環境には lld が無い。

### 提出の前にレビューの観点を自分で見る

reviewer に渡る前に、次を自分で確かめる。差し戻しの周回が減る。

- 期待値を `assert_eq!` で値ごと比べている。
  `is_err()` や `matches!` だけで済ませていない。
- 秘密の値が、エラーの文、`Display`、`Debug`、ログに出ない。
- brief のテスト名、触ってよいファイル、決まった設計から外れていない。
- 空の入力の振る舞いをテストしている。

## 親セッションがすること

- 重いビルドを回す担当は、メモリに合わせて同時に3本までにする。
  swap が埋まりかけていたら、新しい担当を起こさない。
  swap の量は `sysctl vm.swapusage`(macOS)か `free -h`(Linux)で見る。
- 読むだけの担当(レビュー、brief を書く担当)は、ビルドの本数に数えない。
- ディスクの空きを見張る。
  空きが 15GB を切ったら、新しい担当を起こさず、置き場を片づける。
  空きは `df -h .` で見る。裏で `df` を1分ごとに見て、切ったら知らせる見張りを置く。
- main に入った単位の worktree は、`git worktree remove --force` で片づける。
  消す前に、`git status --porcelain` でコミットしていない変更が無いことを確かめる。
  ブランチは残すので、作業は失われない。
- 担当の単位は、手元の軽い検査と reviewer の合格のあとに、統合用のブランチへ取り込む。
- PR は統合用のブランチから main への1本にまとめる。
  PR の前の diff-review と、CI の `check`(カバレッジ100%)をそこで1回ずつ回す。
  CI で落ちたら統合用のブランチで直す。
- 作業ブランチへの push は、統合が済んだときに1回にまとめる。
  CI は新しい push で走っている分を取り消す。
  mutation のジョブが最初からやり直しになる。
- CI を待つ間に、次の段の担当を起こす。
