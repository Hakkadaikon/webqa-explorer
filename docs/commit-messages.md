# コミットメッセージの規約

[Conventional Commits 1.0.0](https://www.conventionalcommits.org/ja/v1.0.0/)に従う。
種類と範囲は英語で、要約と本文は日本語で書く。
形式は、lefthookのcommit-msgフックとCIが検査する。

## 形式

```text
<種類>(<範囲>)!: <要約>

<本文>

<フッター>
```

必須なのは1行目(ヘッダー)だけで、範囲と`!`は省ける。
本文やフッターを書くときは、その前に空行を1行入れる。

## 種類

| 種類 | 使う場面 |
|---|---|
| `feat` | 利用者から見える機能を足す |
| `fix` | 不具合を直す |
| `docs` | 文書だけを変える |
| `style` | 動作に影響しない書式だけを変える |
| `refactor` | 振る舞いを変えずにコードを整理する |
| `perf` | 性能を上げる |
| `test` | テストを足す、直す |
| `build` | ビルドの設定や依存を変える |
| `ci` | CI の設定を変える |
| `chore` | 上のどれにも当たらない作業(開発ツールの設定など) |
| `revert` | 以前のコミットを取り消す |

## 範囲

変更の主な対象を、英小文字・数字・ハイフンで書く。
ディレクトリやモジュールの名前を使う(例: `metrics`、`ci`)。
複数の対象にまたがるときは省く。

## 要約

- 日本語で書く。ひらがな・カタカナ・漢字を1字以上含める。
- 50字以内に収める。
- 文末に句点やピリオドを付けない。
- 何をするかを現在形で書く(例: 「CCNの上限を判定に加える」)。
- 「〜した」の過去形にしない。
- 抽出台帳やテスト台帳の管理番号、設計手法の名前を書かない。

## 本文

本文には、なぜ変えるのかと、何が変わるのかを書く。
どう変えたかはコードを読めば分かるので、書かない。
1行は72桁以内にし、全角文字は2桁と数える。
ただしURLを含む行は、長さの検査から外れる。

## フッター

- `<トークン>: <値>`の形で書く(例: `Refs: #12`)。
- 共同作業者は`Co-Authored-By: <名前> <メールアドレス>`で書く。
- 互換性を壊す変更は、ヘッダーの`:`の前に`!`を付ける。
- そのうえでフッターに`BREAKING CHANGE: <説明>`を書く。

## 例

```text
feat(metrics): 認知的複雑度の上限を判定に加える

rust-code-analysis の cognitive を読み、4 を超えた関数を報告する。
clippy の cognitive_complexity と同じ閾値にそろえる。

Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
```

## 検査の対象外

- gitが作るメッセージは検査しない。
- 具体的には`Merge`、`Revert "`、`fixup!`、`squash!`、`amend!`で始まるもの。
- この規約より前の英語のコミットは、そのまま残す。

## 検査の仕組み

判定は`scripts/commit_msg.py`が行い、lefthookのcommit-msgフックがコミットのたびに走らせる。
このフックは`just setup`で入る。
CIは、PRに含まれるコミットをすべて判定する。
そのため`--no-verify`でフックを飛ばしたコミットも、CIで捕まる。
手元で試すときは`just commit-msg <ファイル>`を使う。
