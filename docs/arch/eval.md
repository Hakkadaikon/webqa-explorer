# インタビューのモードの課題を測る

インタビューのモードが出す課題が、本物の使いにくさをどれだけ捉えるかを数字で測る。
既知の使いにくさを仕込んだ小さなサイトで回し、仕込みと台帳の課題を突き合わせて、再現率と適合率を出す。
数字は、インタビューのモードを作り込み続けるかを決める材料にする。
判断の線は先に決めず、種類ごとの数字と課題の中身を見て決める。
同じ物差しで、直しの前後も比べられる。

測定は手元で手動で回し、CIでは回さない。
部品は`crates/webqa-eval`にあり、台帳は`webqa-core`の`interview::ledger::read`で読む。
`webqa`のCLIには何も足さない。

## 仕込みのサイト

`eval/site/`に、勤怠管理システムを比べる比較サイトの小型版を静的なHTMLで置く。
`just eval`は、`webqa-eval serve`でこのサイトを`127.0.0.1`の空いたポートで配る。
`file://`はガードレールの許可するオリジンを作れないので使わない。

| 画面 | パス | 役目 |
|---|---|---|
| トップ | `/` | 検索欄と分類へのリンク |
| 検索結果 | `/search.html` | 検索語に合う製品の一覧 |
| 分類の一覧 | `/attendance.html` | 勤怠管理の製品の一覧のはずの画面 |
| 製品の詳細 | `/product-a.html`、`/product-b.html`、`/product-c.html` | 機能と料金 |
| 資料請求 | `/request.html` | 入力欄と送信 |

仕込みは7件あり、台帳の4つの種類に2件ずつ(「目的に届かない」は1件)置いた。
仕込んだところ以外は、ラベルの付いたリンクとボタンを、読める大きさと色で作る。

| id | 種類 | パス | 要素 | 仕込み |
|---|---|---|---|---|
| `faint-price-link` | `visibility` | `/product-a.html` | link 料金を見る | 薄い灰色で小さな字のリンク |
| `invisible-filter` | `visibility` | `/attendance.html` | button 条件 | 文字の色が背景と同じで見えないボタン |
| `next-or-go` | `hesitant` | `/attendance.html` | button 次へ | 意味の違いが書かれていない「次へ」と「進む」が並ぶ |
| `same-name-links` | `hesitant` | `/search.html` | link 詳しく | 同じ名前のリンクが3つ並ぶ |
| `no-compare` | `unreached` | 省く | 省く | 料金を比べる画面`/compare.html`へのリンクがどこにも無い |
| `title-not-products` | `mismatch` | `/attendance.html` | 省く | 題は「人気の製品」だが、中身は記事の一覧 |
| `request-asks-signup` | `mismatch` | `/request.html` | 省く | 資料請求の画面なのに、会員登録を求めている |

## 設定

回す設定は`eval/`にある。

| ファイル | 中身 |
|---|---|
| `eval/persona.yaml` | 総務担当の田中さん |
| `eval/purpose.yaml` | 勤怠管理システムを料金と機能で比べ、候補を絞る目的。`/compare.html`に着けば達成とし、5画面の役目を書く |
| `eval/config.yaml` | `webqa interview`の設定。`target.url`は`__URL__`で、`just eval`が配信のURLに置き換える。試行は3回 |

`interview.persona`と`interview.purpose`のパスは、設定ファイルの場所ではなく、`webqa`を起動した作業ディレクトリから読まれる。
`just eval`はリポジトリの直下で回すので、`eval/`からの相対で書く。
判断モデルは`bridge/jev.py`で、JEV 1.14.0とHaiku 5.5を使う。
キーは作業ディレクトリの`.env`の`WEBQA_JUDGE_API_KEY`から読むので、本体のcheckoutの直下で回す。
検索欄には、環境変数`WEBQA_SEARCH`の値を伏せずに入れる。

## 正解表と人の判断

正解表`eval/truth.yaml`は、仕込みごとに1件を書く。

| 項目 | 中身 |
|---|---|
| `id` | 仕込みの名前 |
| `kind` | 種類の識別子。`visibility`、`hesitant`、`unreached`、`mismatch`のどれか |
| `path` | 画面のパス。目的のずれは、目的の文書に書いた型と同じ文字列。省くと、パスは照合しない |
| `element` | 役割`role`と名前`name`。ブラウザのアクセシビリティ名で書く。省くと、要素は照合しない |
| `note` | 何を仕込んだか |

種類は、表示名の文言を変えても照合が壊れないよう、識別子で書く。
目的に届かない課題は、試行が止まる画面を前もって決められないので、`path`を省いて種類だけで突き合わせる。

人の判断`eval/labels.yaml`は、仕込みに当たらなかった課題に、人が判断を付ける。
キーは種類、パス、要素(あれば)で、値`verdict`は`real`(本当に使いにくい)か`false`(誤り)である。
パスと要素を省いた判断は、何にでも合う。
一度付けた判断は、次の測定でも使う。
判断の無い課題は、未判定として一覧に出す。
最初は空(`[]`)で始める。

## 採点の数え方

`webqa-eval score`は、台帳と正解表と人の判断を読んで採点する。

- 台帳の課題のうち、本体と、確かめられなかった課題を数える。ペルソナから外れると判断した課題は数えない。
- 課題と仕込みは、種類が同じで、仕込みにパスがあればパスも同じで、仕込みに要素があれば要素も同じときに当たりとする。
- 再現率は、当たった仕込みの数を、仕込みの数で割る。
- 厳しい適合率は、仕込みに当たった課題の数を、課題の数で割る。
- 人の判断を引いた適合率は、仕込みに当たった課題と`real`の課題の数を、課題の数から未判定の数を引いた数で割る。

分母が0の数字は`-`と出す。
結果は、種類ごとと全体の表、見つからなかった仕込み、未判定の課題の一覧にする。
同じ設定を複数回回したときは、回ごとの平均とばらつきを出す。

## 回し方

```text
just eval
just eval 1
```

引数は、設定を回す回数で、既定は3回である。
`just eval`は次の順に進む。

1. `webqa-eval serve eval/site`でサイトを立て、URLを`target/eval/<日時>/url`に書く。
2. `eval/config.yaml`の`__URL__`をそのURLに置き換える。
   この設定で`webqa interview`を、回す回数だけ回す。
3. すべての回の`ledger.md`を採点し、表を`target/eval/<日時>/report.md`に書く。

費用の目安は、1回(試行3回)でおよそ1ドルである。
本物の判断モデルを呼ぶので、回す前に単価を確かめる。

結果は`tasks/eval/<日付>.md`に残す。
数字、見つからなかった仕込み、課題の中身の所見、費用を書く。
