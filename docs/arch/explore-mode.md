# 探索モード

## 目的

探索モードは、手順を書かずに対象のWebサービスを広く操作し、問題を探す。
次の操作は判断モデルが選び、候補は中核がまだ操作していない要素へ絞る。
探索の記憶を実行をまたいで残すので、続けて実行すると前回までに操作した要素を後回しにする。

## 入力

探索モードは次のコマンドで動かす。

```text
webqa explore --config <設定> [--out <出力先>]
```

出力先を省くと`.webqa`に書く。
引数と終了コードは[cli.md](cli.md)にまとめた。

探索モードが読む設定の項目は次のとおり。
項目の形と既定値は[config.md](config.md)にある。

| 項目 | 探索モードでの使い道 |
|---|---|
| `target.url` | 開始のURL |
| `target.allowed_origins` | 探索してよいオリジン |
| `judge` | 次の操作を選ぶ判断モデル |
| `limits` | 固まりと行き詰まりの閾値、判断予算、時間窓の上限、ページの待ち時間、制限時間、確信度の閾値 |
| `guard` | 禁止要素、許可リスト、課金画面から離れる操作 |
| `redact` | 伏せる値 |
| `inputs` | 入力欄に打つ値 |
| `auth.storage_state` | 認証状態 |
| `ops` | 判断モデルに選ばせる操作の種類 |

探索モードは`scenario`を読まない。
`ops`に`click`も`input`も無いと、設定エラーで起動しない。
要素を操作できなければ、探索が進まないためである。

## 振る舞い

1つのステップは、観測、判断、ガードレール、操作の順に進む。
状態遷移の全体と、ステップの間で調べる条件の順番は[core.md](core.md)に書いた。
ここでは探索モードに固有の振る舞いを書く。

1. ページを観測し、探索の記憶に画面を足す。
2. 中核が候補の段を決め、その段だけを選択肢にして判断モデルに問う。
3. 判断モデルが選んだ操作を、ガードレールに通す。
4. 通った操作をブラウザで行い、移った先の画面を探索の記憶に記録する。

### 判断モデルへの問い

判断モデルには、操作の種類、対象の要素、画面にエラーの表示があるかを問う。
対象の要素の問いでは、判断モデルが要素の番号に順位を付けて答える。
画面が最後に変わってから操作した要素は、飛ばして次の順位の要素を選ぶ。

探索モードでは、判断モデルに`done`を選ばせず、ゴールも渡さない。
操作の種類の選択肢から`done`を外すので、判断モデルの宣言だけで終わることは無い。
それでも`done`が返ってきたら、選択肢に無い答えとして応答の異常に数える。

### 終わり方

探索モードは、次のどれかで終わる。

| 終了理由 | 起きるとき |
|---|---|
| ゴール達成(`goal_achieved`) | 判断モデルに1回以上問い合わせたうえで、開始の画面から辿れる画面に未操作の要素が無くなった |
| 行き詰まり(`stuck`) | 進展の無いステップが`limits.stuck_threshold`に達した。または判断モデルが`stuck`を選んだ |
| 判断予算切れ(`budget_exceeded`) | 問い合わせの回数が`limits.max_decisions`に達した |
| 時間切れ(`time_exceeded`) | 経過時間が`limits.max_duration_secs`に達した。時間窓が満杯で、次の窓が明けるのがそれと同時か後のときも含む |
| 中断(`user_aborted`) | 利用者が止めた |

開始の画面は、許可ドメインの中で最初に観測した画面である。
未操作の要素には、禁止要素を数えない。
探索の記憶は前回の実行から引き継ぐので、前回までに操作した要素も操作済みに数える。
進展の数え方は[core.md](core.md)に、判断予算と制限時間は[safety.md](safety.md)に書いた。

## 出力

1回の実行は、出力先に次のものを書く。

```text
<出力先>/
  runs/<実行ID>/
    events.jsonl   イベントログ
    report.json    実行結果
    screenshots/   問題を見つけた画面
  memory/
    <オリジンを符号化した名前>.json   探索の記憶
```

イベントログ、実行結果、スクリーンショットの中身は[records.md](records.md)に書いた。
探索の記憶の形は、この文書の[探索の記憶](#探索の記憶)にある。

## 設計の詳細

### 要素の範囲

ページの要素は、アクセシビリティ情報から取った操作できる要素である。
要素の一覧は、用途ごとに範囲を分ける。

| 用途 | 範囲 |
|---|---|
| 画面の識別 | ページ全体の操作できる要素 |
| 判断モデルに送る一覧 | 表示領域の中の操作できる要素 |
| 画面が変わったかの判定 | 表示領域の中の操作できる要素とURL |
| 未操作の要素が新しく見えたかの判定 | 表示領域の中の操作できる要素 |

画面はページ全体で識別するので、スクロールしても同じ画面のままである。
一方、表示領域の一覧は変わるので、スクロールは画面の変化に数える。

「未操作の要素が新しく見えた」とは、その画面でまだ表示領域に入っていなかった要素が、表示領域に入ったことをいう。
数えるのは、操作済みでも禁止要素でもない要素だけである。

表示領域の中かどうかは、要素の矩形と表示領域の重なりで決める。
矩形は、`aria_snapshot`に`boxes(true)`を渡して取る。
値は表示領域を基準にしたCSS pxの整数である。
1px以上重なれば中に数え、矩形の無い要素と幅か高さが0の要素は外に数える。
`overflow:hidden`の親に隠れた要素、覆われた要素、`opacity:0`の要素は、この判定では中に数える。

### 画面と要素の識別

画面は、URLのパスと、ページ全体の操作できる要素の集合の組で識別する。
集合の要素は、roleと名前の組である。
クエリ文字列と入力欄の値が変わっても、同じ画面とみなす。

要素は、画面、role、名前、同じroleと名前の中での順番の組で識別する。

識別に使う名前は、伏せ字の処理を通したあとの名前である。
探索の記憶は伏せ字のあとで保存するので、別の名前で識別すると次の実行で画面が一致しない。
その名前を、さらに次のように正規化してから使う。

- 前後の空白を除き、空白の連なりを1つの空白にする。
- 数字の連なりを1つの`#`にする。全角の数字も数字に数える。

こうすると「通知 (3)」と「通知 (4)」は同じ要素になり、件数や時刻が変わっても画面は増え続けない。
正規化した名前は識別だけに使う。
判断モデルに送る一覧の名前は、伏せ字の処理だけを通し、正規化はしない。

### 探索の記憶

探索の記憶は、対象のオリジンごとに1つのグラフである。
節は画面、辺は「どの画面のどの要素をどう操作したら、どの画面へ移ったか」である。
画面の各要素には、操作済みかと禁止要素かの印を付ける。

探索の記憶は、探索モードと決め打ちシナリオのどちらの実行でも更新する。
候補の絞り込みとゴールの判定に使うのは、探索モードだけである。

ファイルの形は次のとおり。

```json
{
  "schema": 1,
  "origin": "https://app.example.test",
  "screens": {
    "s1": { "path": "/", "elements": [
      { "role": "button", "name": "保存", "nth": 0,
        "operated": true, "forbidden": false }
    ] }
  },
  "edges": [
    { "from": "s1", "element": { "role": "button", "name": "保存", "nth": 0 },
      "op": "click", "to": "s2" }
  ]
}
```

画面の名前は、`s1`から欠けなく番号を振る。
画面の識別そのものは書かず、読むときにパスと要素から作り直す。
辺の`op`は`click`か`input`である。

### 保存

探索の記憶は、出力先の`memory/`に置く。
ファイル名は、オリジンの英数字と`-`、`.`、`_`、`*`以外の文字を`%XX`に符号化し、`.json`を付けたものである。

実行を始めるときに読み、実行を終えるときに書く。
書く前に伏せ字の処理を通す。
書き込みは一時ファイルに書いてから名前を変えるので、途中で止まっても前の版が残る。

次のファイルは使わず、空の記憶で始める。

| 原因 | 当たるとき |
|---|---|
| `unreadable` | JSONでない、記憶の形でない、画面の番号が欠けている、辺の端が画面に無い |
| `schema` | `schema`が1でない |
| `origin` | `origin`が対象のオリジンと違う |

使えなかったファイルは、名前に`.broken-<実行ID>`を足した名前に移し、上書きで失わないようにする。
空の記憶で始めたことと原因は、イベント`memory_reset`に残す。

再実行(`webqa replay`)は、実行結果に残した開始時の記憶から始め、`memory/`のファイルを読みも書きもしない。
再実行の詳細は[records.md](records.md)にある。

### 候補の絞り込み

探索モードの候補は、中核が次の段に分ける。

1. 今の画面の未操作の要素(禁止要素を除く)
2. 未探索の分岐が残る操作済みの要素(禁止要素を除く)
3. 戻る、下スクロール、上スクロール

1段目と2段目に入れるのは、表示領域の中の要素だけである。
判断モデルが選べるのは、番号を振って送った要素だけだからである。
表示領域の外にしか未操作の要素が無ければ3段目に落ち、スクロールで表示領域に出す。

中核は、候補のある最上位の段だけを判断モデルに渡す。
1段目と2段目では、対象の要素の問いの選択肢を、その段の要素の番号に絞る。
3段目では、操作の種類の選択肢を`back`、`scroll_down`、`scroll_up`のうち`ops`にあるものに絞る。
`enter`は、その画面で外していなければ3段目にも残す。
判断モデルはその中から選ぶので、段の優先順位は判断モデルの答えに関わらず守られる。
選択肢に無い要素や種類を答えたら、応答の異常に数える。
3段目の種類が`ops`に1つも無いときは、絞らずに`ops`の種類と表示領域のすべての要素を選択肢にする。
3段目で種類を絞るときは選べる要素が無いので、対象の要素の問いは送らない。

ある要素を「探索し終えた」かは、中核が探索の記憶のグラフをたどって求める。
操作済みの要素から移った先の画面と、そこから辿れる画面に、禁止要素でない未操作の要素が残っていれば、まだ探索し終えていない。
たどるときは、その要素のある画面を最初から「たどった画面」に入れておく。
そのため、自分の画面に戻る辺と、自分の画面を通る循環は、未探索の分岐に数えない。
自分の画面に残る未操作の要素は、1段目かスクロールで拾うからである。
循環があっても止まるよう、たどった画面を覚えておく。

### 操作の種類

探索モードでは、`ops`に書いた種類を判断モデルに渡す。
`ops`を省くと、すべての種類を使う。
`done`を外すことは[判断モデルへの問い](#判断モデルへの問い)に書いた。

| 操作 | 対象 | ブラウザでの振る舞い | 探索の記憶への記録 |
|---|---|---|---|
| `click` | 要素 | 要素を押す | 要素を操作済みにして辺を足す |
| `input` | 入力欄 | `inputs`の値を打つ | 値を打ったときだけ、要素を操作済みにして辺を足す |
| `scroll_down` | なし | 表示領域の高さの8割だけ下へスクロールする | 記録しない |
| `scroll_up` | なし | 表示領域の高さの8割だけ上へスクロールする | 記録しない |
| `back` | なし | ブラウザの履歴を1つ戻る | 記録しない |
| `enter` | なし | フォーカスが入力欄にあるときだけ、Enterキーを押す | 記録しない |
| `wait` | なし | 何もせず、次の観測でページの変化を見る | 記録しない |
| `stuck` | なし | 行き詰まりを宣言して実行を終える | 記録しない |

要素を操作して許可ドメインの外へ移ったときは、移った先を元の画面とみなして辺を記録する。

`back`は、判断モデルの確信度が`limits.back_confidence`未満なら止める。
ガードレールの全体は[safety.md](safety.md)に書いた。

#### 入力欄への入力

`input`は、入力欄の読み上げ名と同じ`inputs`のキーの値を打つ。
入力欄は、roleが`textbox`、`searchbox`、`combobox`、`spinbutton`の要素である。

入力欄でない要素と、値の無い入力欄には何も打たず、イベント`skipped`を残す。
原因はそれぞれ`not_an_input`と`no_input_value`である。
何も打たなかった`input`は、探索の記憶で操作済みに数えない。

候補の段に値のある入力欄が1つも無ければ、操作の種類の選択肢から`input`を外す。
ただし、`input`のほかに選べる種類が無いときは`input`を残す。

#### Enterキーの入力

`enter`は、フォーカスのある要素でEnterキーを押す操作で、対象の要素を取らない。
入力欄に値を打ったあと、フォームを送るのに使う。
ブラウザは、フォーカスが入力欄にあるときだけ押し、そうでなければ何もしない。
ボタンの上でEnterキーを押すと、そのボタンを押したのと同じになるためである。
入力欄に数えるのは、`textarea`、`select`、編集できる要素と、型が`text`、`search`、`email`、`url`、`tel`、`number`、`password`の`input`要素である。

`enter`は探索の記憶に記録しない。
画面が変われば、変わった先の画面が記憶に加わる。

禁止要素のある画面では、どのモードでも`enter`を外す。
理由は[safety.md](safety.md)の「禁止要素とenter」に書いた。
探索モードでは、表示領域の中に`inputs`に値のある入力欄が1つも無い画面でも、`enter`を外す。
値を打った入力欄は操作済みになって候補から外れるので、候補ではなく表示中の要素で決める。
`input`と違い、`enter`しか残らないときも外す。

#### 名前の比べ方

名前を比べるとき、中核は伏せ字の処理を通した名前を使い、ブラウザは生の名前を使う。
伏せ字で名前が変わる入力欄では、両者の判断がずれることがある。
`inputs`のキーには伏せ字を通す前の名前を書き、`[[名前]]`の形では書かない。
