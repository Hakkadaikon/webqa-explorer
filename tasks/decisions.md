# 決めたことの記録

利用者が席を外している間に、親のセッションが決めたことを並べる。
利用者が決めたものは「利用者」と書く。
仕様(feature、TLA+)を変えたものは「仕様」と書く。
戻ったら、この一覧で確かめてもらう。

重要な決定は、決めたあとにサブエージェントにもレビューさせ、結果を各行に添える(利用者、2026-10-20)。
仕様の決定は loop-engineering-reviewer、設計の決定は reviewer が見る。TLA+ を変えたら modeler でモデル検査を通す。

## 2026-10-20

### 進め方

- 全体のテストとカバレッジ100%を、コミット前のフックから外し、PR の CI の `check` で確かめる(利用者)。ゲートの閾値と強さは変えていない。
- PR は統合用のブランチから main への1本にまとめ、diff-review と CI はそこで1回ずつ回す。単位ごとの PR は diff-review のフックのため出さない。
- push と、diff-review の must 0 と CI の `check` が緑の PR のマージは、そのつど聞かずに行う(利用者)。
- CI の mutation は `--shard` で4つのジョブに分ける(利用者)。
- sccache を aqua に足す。置き場を分けるときは `--target-dir` で渡す。
- 実物の実行は、許可のある相手(Playwright の TodoMVC デモ)だけ。費用は合計10ドルまで(利用者)。it-trend.jp は許可が無いので回さない(利用者)。

### 14c〜14m

- 一時ファイルは、作る段階の失敗でも置き場を消す(14c)。macOS と Linux で振る舞いをそろえるため。
- `Ports` の失敗の印は `log` とスクリーンショットだけに効き、`store()` を通る書き込みは呼び手が止める(14d)。
- `Ports::new` の既定の `Detect` を必須の引数にする案は見送り、14g で配線を確かめるテストを置く。
- `--timeout` は橋渡しの要求の1行あたりの予算。上限は3600秒。リダイレクトは辿らない(#59)。
- 時計は判断モデルとブラウザの起動のあとから数える。判断モデルには別の時計を渡す(14g)。文書の「実行の開始から測る」と `elapsed_ms: 0` に合わせた。
- Playwright の Ctrl-C の処理は `PLAYWRIGHT_NO_SIGNAL_HANDLER` で止める。スレッドが1本のうちに立てるので安全(14g)。
- `replay` が出力先の記憶を読む問題は #61 に切り出した。直し方は、元の実行の開始時の記憶を残し、replay はそこから始める。
- 偽物の置き場(`FakeInterrupt` など)は、brief どおり各テストに置いたままにする(14f)。
- 受け入れの `check_fakes` は残す。消すには `fakes.rs` を変える必要があり、brief に反する(14h)。
- 台帳の読み込みは、ループが1行ずつ進める形に組み替えた。mutation の待ち時間切れを、テストの失敗で捕まえられるようにするため。

### 実物の実行で見つかったもの(#62、#63、#64)

- 探索モードでは、対象に合わない操作を選択肢から外し、記憶にも数えない(利用者、仕様)。
  - その段の候補に、入力欄で設定に値のある要素が無ければ、操作の種類から `input` を外す。
  - 何も起きなかった `input` は操作済みにしない。
  - 値の無い入力欄への `input` は `skipped` で記録する。
  - feature の「操作種別の選択肢は7種」を、この形に直す。

### #61、#57

- #61: 元の実行の開始時の記憶を `report.json` の `start_memory` に入れ、replay はそこから始めて共有の記憶に書かない。`start_memory` の無い古い実行結果は空の記憶から始める。形式の版は1のまま。
- #57: tears は使わず、注入した時計で200ミリ秒ごとに読む。端末を raw モードにせず、Ctrl-C だけで終わる。`run_finished` を読んだら読むのをやめ、最後の画面を残す。依存は `webqa-tui` に `crossterm`(ワークスペースにある 0.29.0)を足すだけ。

### #30、#31

- #30: 台帳は1回の実行で1つ、`events.jsonl` も1つで `trial_started`/`trial_finished` を書く。前回の台帳の頭は試行の前に確かめ、`compare` の `Mismatch` は安全のための腕として残す。`Ports` に `interview: Option<Interviewing>` を足し、`perform::ask` で分ける。確定の問題の検出(#8)はインタビューの試行でも動かし、終了コード1はそれだけで決める。
- #31: サブコマンドは `webqa interview` と `webqa check-docs persona|purpose <file>`。前回の台帳の頭が合わなければ設定エラー(終了コード2)。
- 仕様: feature の「再実行と照らし合わせ」に「前回の台帳の頭が合わなければ設定エラーにする」シナリオを足す。
- テスト項目の台帳: T-042(`other_modes_send_text_only`)と T-089(スクリーンショットの名前)の受け持ちを #31 から #30 へ移す。
