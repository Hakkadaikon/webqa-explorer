## 受け持つシナリオ

### 判断モデルへの問い(14本)

- インタビューのモードでは、画像を扱えると申告したアダプタに、アクセシビリティ情報のテキストとスクリーンショットを渡す
- 探索モードと決め打ちシナリオでは、これまでどおりテキストだけを渡す
- 外部コマンドへの問いの JSON に、特定のモデルに依らない形で画像を入れる
- 判断モデルのアダプタは、どれも起動のときに画像を扱えるかを申告する
- 橋渡しは起動のときに、JSON の版の項目で画像を扱えるかを申告する
- スクリーンショットは伏せずに渡す
- 毎ステップの問いにペルソナの説明を添えて、この人ならどうするかを問う
- 1ステップで今の4つの問いに加えて、迷い・期待・見えにくい要素・画面の目的を問う
- 目的を書いたときも、画面の目的の推測を問う
- 期待や理由は、自由な文の答えとしてそのまま受け取る
- 足した問いの答えが欠けていたら、応答の異常として扱う
- 足した問いの答えが範囲の外なら、応答の異常として扱う
- 操作の対象は候補を絞らず、表示領域の操作可能要素から判断モデルに選ばせる
- インタビューのモードでは、操作種別の選択肢に done を入れる

### 試行の終わり方(7本)

- 目的の done_when を満たしたら、判断モデルに問い合わせずにゴール達成で試行を終える
- 目的の確定のボタンが禁止要素でも押さず、確定の操作ができる画面に来たところでゴール達成にする
- 目的を推測させたとき、判断モデルの done は推測した目的に届いたという申告として記録する
- 目的を書いたのに done_when を満たさないまま done が返ったら、未検証の終了として記録する
- 判断モデルが stuck を返したら、ペルソナが諦めたものとして行き詰まりで試行を終える
- 打ち切りでない試行のうち、ゴール達成と申告による終了のほかで終わった試行は、目的に届かない試行に数える
- ゴール達成や申告による終了で終わった試行は、目的に届かない試行に数えない

### ペルソナから外れないこと(6本)

- 試行をまとめたあと、課題の番号ごとに1回だけ、そのペルソナとして自然かを別の問いで確かめる
- 自然さの問いの回数の上限を超えた課題は、確かめられなかった区分に入れる
- 自然だと判断した課題は、台帳の本体に入れる
- 自然でないと判断した課題は、本体に入れず、最後の別の節にまとめる
- 自然さの問いの応答が使えないときは、本体に入れず確かめられなかった区分に入れる
- 台帳の各課題に、ペルソナのどの性質からそう判断したかを書く

名前は、Rule のファイルの `READY` に入れる。

### 判断モデルへの問い

- 判断モデルのアダプタが、起動のときに画像を扱えると申告している
- 判断モデルに、アクセシビリティ情報のテキストと、画面のスクリーンショットを渡している
- <p>で1ステップを実行する
- 判断モデルに渡したのはアクセシビリティ情報のテキストだけで、スクリーンショットは含まれない
- 判断モデルとして外部コマンドとの橋渡しを使う設定である
- 外部コマンドに書いた問いの JSON に、画像を渡す項目がある
- その項目の名前と形は、判断モデルの種類の設定を変えても変わらない
- 判断モデルとして <p> を使う設定である
- 実行を始めてアダプタを起動する
- アダプタの画像を扱えるかの申告を読み、それに合わせて問い合わせを作っている
- 実行を始めて橋渡しを起動する
- 橋渡しが返した JSON の版の項目から、画像を扱えるかの申告を読んでいる
- 判断モデルに渡したテキストではメールアドレスが伏せられている
- 判断モデルに渡したスクリーンショットは、画面をそのまま写したものである
- 判断モデルへの問いに、ペルソナの文書の名前、どんな人か、ITの慣れ、達成したいこと、しないことが添えられている
- 問いは、このペルソナならどうするかを尋ねる形である
- 判断モデルに次の項目を1回の問い合わせで問うている
- 目的として {string} とその done_when を書いている
- 判断モデルへの問いに、画面の目的の推測が含まれる
- 判断モデルが、期待を自由な文 {string} で答える
- その文が、そのステップの期待として記録されている
- 判断モデルの応答に <p> が無い
- 判断モデルの呼び出し回数は {n} 増えている
- 判断モデルの応答の <p> が <p> である
- 表示領域に、操作済みの要素 {string} と未操作の要素 {string} がある
- 対象要素の問いの選択肢に {string} と {string} の両方が含まれる
- 判断モデルが {string} を選べば、ガードレールを通ったあとに {string} をクリックしている
- 操作種別の問いの選択肢に done が含まれる

### ペルソナから外れないこと

- 判断モデルとして、台本どおりに答えるスタブを使う
- 番号 {string} の判断に迷う課題が、3回の試行のうち2回で起きている
- すべての試行を終えて台帳を書く
- スタブに、{string} について、このペルソナがこの場面でこう考えこう操作するのは自然か、という問いが1回だけ届いている
- その問いは、1ステップの問いとは別の問い合わせで、判断予算に数えられていない
- 台帳の並びの順に、課題 {string}、{string}、{string} がある
- 自然さの問いは {string} と {string} について1回ずつ、計 {n} 回だけ問われている
- {string} は、確かめられなかった区分にある
- 確かめられなかった区分は、台帳の本体の後、ペルソナから外れると判断した課題の節の前にある
- 自然さの問いに、判断モデルが自然だと答える
- その課題は台帳の本体にある
- 課題 {string} の自然さの問いに、判断モデルが自然でないと答える
- その課題は台帳の本体に無い
- その課題は台帳の最後の、ペルソナから外れると判断した課題の節にある
- 自然さの問いへの判断モデルの応答が、形式の崩れた応答である
- その課題は、確かめられなかった区分にある
- 判断モデルが、迷った理由として、ペルソナの ITの慣れ {string} を挙げる
- その課題に、ペルソナの性質 {string} とその中身が書かれている

`{string}`、`{int}`、`{float}` 以外の広いパラメータと正規表現は使わない。Examples の値で手順を分ける必要があるときは、値から場面への対応表で引く。手順の中に `if` を書かない。

## 場面の組み立てと使う製品の口

- 判断モデルへの問いは、偽物の判断モデルの記録(問いの種類、選択肢、画像の有無、自由な文の問い)で確かめる。インタビューのモードでは画像を送る。画像を読まない判断モデルの場面も作る。
- 試行の終わり方は、#21 の `Ended`(ゴール、行き詰まり、時間切れほか)と中核の終了理由の写し方を、台帳とイベントの行で確かめる。
- ペルソナから外れないことは、ペルソナの「しないこと」に当たる操作を判断モデルが返したときの扱いを確かめる。応答の異常は共通の手順「応答の異常として記録されている」で確かめる。

## 注意

- 壊れたときに止まり続けるテストを書かない。`tokio::time` はこのクレートで禁止なので、待つなら std の `recv_timeout` か `tests/support/stuck.rs` を使う。
- シナリオを通すために Then の確かめを緩めない。Given の場面を feature と違うものにしない。親のまとめてのレビューは、何も確かめずに通るシナリオを must として探す。
- 期待値は値ごと比べる。Debug の文字列や部分一致で済ませない。
