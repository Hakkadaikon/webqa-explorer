## 決めてある設計

### 場面の部品(この Rule の中だけで使う。`ending.rs` に置く)

- **行き詰まりの画面**: 開始の画面を、次の3つの画面のどれかにする(要素の集合が同じなので、記憶の中では同じ画面)。
  - `SHOWN`: `button("保存")`、`link("ヘルプ")`、`link("通知設定").below()`
  - `HIDDEN`: `button("保存").below()`、`link("ヘルプ")`、`link("通知設定").below()`(表示領域の一覧から "保存" が消えるので、画面は変化する)
  - `REVEALED`: `button("保存")`、`link("ヘルプ")`、`link("通知設定")`(T-073 で "通知設定" が表示領域に現れる)
  開始の画面は `SHOWN`。前の実行の記憶に、この画面と "保存" の操作(自分の画面への辺)を `remember` で入れる。"ヘルプ" は最初から表示領域にあるので「新しく見えた」に当たらない。"通知設定" は `REVEALED` を見せるまで表示領域に現れない。
- **進まない操作** `no_progress(world, n)`: `Reply::op("scroll_down", 0.9)` を n 回積み、`after` に `HIDDEN`、`SHOWN` を交互に積む(どの回も画面は変化し、操作済みの要素は増えず、未操作の要素も新しく見えない。行き詰まりの回数だけが1ずつ進み、固まりの回数は0のまま)。交互の順は、`after` の最後の画面の続きにする。
- **止める答え** `held(world, n)`: `Reply::op("back", 0.5)` を n 回積む(低確信度の「戻る」で止まる。回数は変わらず、判断予算だけを1つずつ使う)。
- **呼び出し済みの数** `marks["called"]`: 「n 回呼び出し済み」の手順が入れる。後の手順「done_when 条件は満たされておらず、行き詰まりも検出されていない」が、答えの列を最後の n 個に切り詰める(共通の手順「操作しても画面が変化しないステップが 3 回続いている」が答えを3つ足すため。T-023)。
- **時間切れの印** `marks["time_up"]`: 「制限時間に達している」が入れる。制限時間を60秒にし、答えが積まれていれば最後の答えを `.at(60秒)` に、無ければ `clock_start` を60秒にする。答えの列を変える後の手順は、印があれば同じことをやり直す(`settle_time(world)`)。
- **ゴールの印** `marks["goal"]`: 「done_when 条件が満たされている」(この Rule の文)は、段階を `[("ログイン", "ログインする", text "ようこそ")]` にし、印を入れて `apply_goal(world)` を呼ぶ。`apply_goal` は、`after` があれば最後の画面のテキストを `"ようこそ"` にし、`after` が無く答えも無ければ開始の画面のテキストを `"ようこそ"` にし、答えはあるが `after` が無ければ(止める答えはブラウザを操作しないので画面を消費しない)何もしない。`after` を作り直す後の手順は、印があれば `apply_goal` を呼び直す。
- **`after` は操作の数だけ**: 偽のブラウザは操作のたびに `after` を1つ取る。止める答え(`back` 0.5)と応答の異常は操作しないので取らない。`after` を組む手順は、答えの列のうち操作になるものの数だけ積む。

## 親に決めてほしいこと

1. **探索済みの要素を前の実行の記憶で与えること**。「探索済みの要素は "保存" だけである」で "保存" をクリックする問い合わせを積むと、T-018 の「問い合わせ回数は 3 回」が4回になる。前の実行の記憶に "保存" を操作済みとして入れる形にした(記憶は実行をまたいで引き継がれる要件のとおり)。
2. **「n 回呼び出し済み」と共通の手順が重なるときに、答えの列を切り詰めること**(T-023)。共通の手順「操作しても画面が変化しないステップが 3 回続いている」は答えを3つ足すので、そのままでは呼び出しが7回になる。後の手順で、最後の n 個だけを残す形にした。読み手には分かりにくいので、手順の関数の doc コメントにこの理由を書く。
3. **「その後、…2回続いても実行は終了しない」を、場面を足して回し直して確かめること**(T-019、T-073)。cucumber の Then のあとに実行を続ける仕組みは無いので、同じ場面に2回の進まない操作を足し、最初から回し直す。最初の実行と同じ答えと画面を通るので、結果は続けた場合と同じになる。
4. **時間を判断モデルの答えの時刻で進めること**。偽の時計は眠ったときと答えの時刻でしか進まない。「制限時間に達している」は、最後の答えを60秒に返した形にした。
