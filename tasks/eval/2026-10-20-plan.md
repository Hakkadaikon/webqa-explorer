# インタビューのモードの課題を測る仕組み 実装計画(#80)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 仕込みのサイトでインタビューのモードを回し、台帳の課題と正解表を突き合わせて再現率と適合率を出す。

**Architecture:** 新しいクレート `crates/webqa-eval`(lib と bin)に、正解表と人の判断の読み込み、台帳からの課題の取り出し、照合と採点、Markdown の出力、静的ファイルの配信を置く。台帳は `webqa_core::interview::ledger::read` で読む。サイトと設定は `eval/` に置き、`just eval` で回す。

**Tech Stack:** Rust 2024(1.99)、serde と serde-saphyr(YAML)、clap、url。

**Spec:** `tasks/eval/2026-10-20-design.md`

## Global Constraints

- 品質ゲートの閾値と設定を変えない。除外の注釈を足さない。`--no-verify` を使わない。
- テストを先に書く。カバレッジは行・リージョン・関数とも100%。
- 依存はワークスペースの `[workspace.dependencies]` から `<name>.workspace = true` で使う。新しい外部クレートは足さない。
- コミットメッセージは日本語の Conventional Commits(`docs/commit-messages.md`)。
- 手元の絶対パスをファイルに書かない。
- 設計からの変更: 正解表と人の判断の種類は、表示名ではなく識別子(`hesitant`、`visibility`、`unreached`、`mismatch`)で書く。結合テストは、台本の判断モデルで回す代わりに、配信と台帳の見本からの採点を確かめる(`webqa` の実行ファイルは別のクレートのテストから呼べないため)。目的に届かない課題は種類だけで照らすので、仕込みは1件にした。

### Task 3: 照合と採点

**Files:**
- Create: `crates/webqa-eval/src/score.rs`、`crates/webqa-eval/src/score/tests.rs`

**Interfaces:**
- Consumes: `Plant`、`Label`、`Verdict`、`KindId`(Task 1)、`Found`(Task 2)
- Produces:
  - `pub fn hits(plant: &Plant, found: &Found) -> bool`: 種類が同じで、`plant.path` が `Some` ならパスが同じで、`plant.element` が `Some` なら要素が同じ。
  - `pub struct Score { pub plants: usize, pub found_plants: Vec<String>, pub missed_plants: Vec<String>, pub issues: usize, pub hit_issues: usize, pub real: usize, pub wrong: usize, pub unlabeled: Vec<Found> }`
  - `pub fn score(plants: &[Plant], labels: &[Label], found: &[Found], kind: Option<KindId>) -> Score`: `kind` が `Some` ならその種類の仕込みと課題だけで数える。仕込みに当たらない課題は、同じ種類・パス・要素の人の判断を引く(判断のパスと要素は `None` なら何にでも合う)。
  - `impl Score { pub fn recall(&self) -> Option<f64>; pub fn strict_precision(&self) -> Option<f64>; pub fn labeled_precision(&self) -> Option<f64> }`: 分母が0なら `None`。
    - `recall = found_plants.len() / plants`
    - `strict_precision = hit_issues / issues`
    - `labeled_precision = (hit_issues + real) / (issues - unlabeled.len())`

```rust
use super::*;
use crate::truth::{Element, Label, Plant, Verdict};

fn plant(id: &str, kind: KindId, path: Option<&str>, element: Option<(&str, &str)>) -> Plant {
    Plant {
        id: id.into(),
        kind,
        path: path.map(Into::into),
        element: element.map(|(role, name)| Element { role: role.into(), name: name.into() }),
        note: String::new(),
    }
}

fn issue(kind: KindId, path: &str, element: Option<(&str, &str)>) -> Found {
    Found {
        number: "I-00000000".into(),
        kind,
        path: path.into(),
        element: element.map(|(role, name)| Element { role: role.into(), name: name.into() }),
    }
}

#[test]
fn a_plant_hits_on_kind_path_and_element() {
    let p = plant("a", KindId::Visibility, Some("/p"), Some(("link", "料金")));
    assert!(hits(&p, &issue(KindId::Visibility, "/p", Some(("link", "料金")))));
    assert!(!hits(&p, &issue(KindId::Hesitant, "/p", Some(("link", "料金")))));
    assert!(!hits(&p, &issue(KindId::Visibility, "/q", Some(("link", "料金")))));
    assert!(!hits(&p, &issue(KindId::Visibility, "/p", Some(("link", "別")))));
    assert!(!hits(&p, &issue(KindId::Visibility, "/p", None)));
    let any = plant("b", KindId::Unreached, None, None);
    assert!(hits(&any, &issue(KindId::Unreached, "/anywhere", None)));
}

#[test]
fn scores_hits_misses_labels_and_unlabeled() {
    let plants = [
        plant("a", KindId::Visibility, Some("/p"), Some(("link", "料金"))),
        plant("b", KindId::Unreached, None, None),
    ];
    let labels = [Label { kind: KindId::Hesitant, path: Some("/".into()), element: None, verdict: Verdict::Real }];
    let found = [
        issue(KindId::Visibility, "/p", Some(("link", "料金"))),
        issue(KindId::Visibility, "/p", Some(("link", "料金"))),
        issue(KindId::Hesitant, "/", None),
        issue(KindId::Visibility, "/q", Some(("link", "x"))),
    ];
    let s = score(&plants, &labels, &found, None);
    assert_eq!(
        (s.plants, s.found_plants.clone(), s.missed_plants.clone(), s.issues, s.hit_issues, s.real, s.wrong, s.unlabeled.len()),
        (2, vec!["a".to_owned()], vec!["b".to_owned()], 4, 2, 1, 0, 1)
    );
    assert_eq!(s.recall(), Some(0.5));
    assert_eq!(s.strict_precision(), Some(0.5));
    assert_eq!(s.labeled_precision(), Some(1.0));
}

#[test]
fn a_false_label_counts_as_wrong() {
    let labels = [Label { kind: KindId::Hesitant, path: None, element: None, verdict: Verdict::False }];
    let s = score(&[], &labels, &[issue(KindId::Hesitant, "/", None)], None);
    assert_eq!((s.wrong, s.real, s.labeled_precision()), (1, 0, Some(0.0)));
}

#[test]
fn a_kind_filter_counts_only_that_kind() {
    let plants = [plant("a", KindId::Visibility, None, None), plant("b", KindId::Unreached, None, None)];
    let found = [issue(KindId::Visibility, "/", None)];
    let s = score(&plants, &[], &found, Some(KindId::Unreached));
    assert_eq!((s.plants, s.issues, s.recall(), s.strict_precision()), (1, 0, Some(0.0), None));
}

#[test]
fn nothing_to_count_gives_none() {
    let s = score(&[], &[], &[], None);
    assert_eq!((s.recall(), s.strict_precision(), s.labeled_precision()), (None, None, None));
}
```

### Task 4: 結果の表と CLI と配信

**Files:**
- Create: `crates/webqa-eval/src/report.rs`(と tests)、`crates/webqa-eval/src/serve.rs`(と tests)、`crates/webqa-eval/src/main.rs`、`crates/webqa-eval/tests/cli.rs`

**Interfaces:**
- Consumes: Task 1〜3 のすべて
- Produces:
  - `pub fn report(runs: &[Vec<Found>], plants: &[Plant], labels: &[Label]) -> String`: 種類ごとと全体の行を持つ Markdown の表。列は「種類、再現率、厳しい適合率、人の判断を引いた適合率」で、値は回ごとの平均と、2回以上なら標準偏差(`0.50 ± 0.10`)。分母が0の回は平均から除き、全回が0なら `-`。表のあとに、見つからなかった仕込み(全回で見つからなかったもの)と、未判定の課題(種類、パス、要素、回数)を箇条書きで出す。
  - `pub fn serve(root: PathBuf) -> std::io::Result<(String, std::thread::JoinHandle<()>)>`: `127.0.0.1:0` で待ち受け、`http://127.0.0.1:<port>/` を返す。パスの `/` は `index.html`。`..` を含むパスと、無いファイルは404。`Content-Type` は `.html` が `text/html; charset=utf-8`、`.css` が `text/css`、ほかは `application/octet-stream`。

    - `webqa-eval score --truth <path> --labels <path> <ledger>...`: 表を標準出力へ。読めないファイルは標準エラーに理由を書いて終了コード2。

```just
# インタビューのモードを仕込みのサイトで回して採点する(本物の判断モデルを使う。本体の checkout の直下で回す)
eval runs="3":
    #!/bin/sh
    set -eu
    cargo build -q -p webqa -p webqa-eval
    out="target/eval/$(date +%Y%m%dT%H%M%S)"
    mkdir -p "$out"
    target/debug/webqa-eval serve eval/site > "$out/url" &
    server=$!
    trap 'kill "$server"' EXIT
    while [ ! -s "$out/url" ]; do sleep 0.1; done
    sed "s#__URL__#$(cat "$out/url")#" eval/config.yaml > "$out/config.yaml"
    i=1
    while [ "$i" -le {{ runs }} ]; do
        WEBQA_SEARCH=勤怠管理 target/debug/webqa interview --config "$out/config.yaml" --out "$out/run-$i" || true
        i=$((i + 1))
    done
    target/debug/webqa-eval score --truth eval/truth.yaml --labels eval/labels.yaml "$out"/run-*/runs/*/ledger.md | tee "$out/report.md"
```
